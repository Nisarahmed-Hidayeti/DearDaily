# DearDaily production and Android status

## Recovery

The project's last recorded backup inspection found no managed backups on its Free plan. Supabase recommends regular off-site logical exports for Free projects. Supabase database backups include Storage metadata, while the actual files require a separate copy. See [database backups](https://supabase.com/docs/guides/platform/backups) and [Storage downloads](https://supabase.com/docs/guides/storage/management/download-objects).

Use a trusted machine and an encrypted volume outside the repository. Use the database connection parameters from the project's **Connect** dialog, preferably the session pooler if direct IPv6 is unavailable. Supply credentials through an access-restricted PostgreSQL password file or a private terminal prompt, never through a shared command, commit or build environment. Keep the same database snapshot for schema, application data and Auth exports where possible. Record the UTC export window and pause application writes if a coordinated database and object snapshot is required.

1. Follow [Supabase's CLI backup and restore guide](https://supabase.com/docs/guides/platform/migrating-within-supabase/backup-restore). Export roles, schema and data into the encrypted volume using `supabase db dump --role-only`, the default schema dump and `supabase db dump --data-only --use-copy`. Verify the dump includes Auth data, especially `auth.users` and `auth.identities`, and contains the application tables. Record any custom Auth or Storage schema changes separately using the guide's schema diff steps.
2. Use scoped Supabase S3 credentials and list every bucket and object, including private journal, profile, public-copy and voice objects. Download using the supported S3 client. Record bucket, key, byte size, content type and local SHA-256 for every object in an encrypted manifest. Compare both inventories and investigate missing references or objects before declaring success.
3. Preserve the exact reviewed revision of `supabase/migrations`, `media-gateway`, `voice-gateway` and shared code. Separately inventory deployed function versions and JWT settings, gateway origin configuration, SMTP, OAuth, Turnstile, redirects, Netlify build flags, and signing fingerprints. Store actual secrets separately under owner control. Database dumps alone cannot restore these settings.
4. Restore into a separate disposable Supabase project or isolated local stack. Keep outbound auth mail disabled during rehearsal. Import roles, schema and data in the documented order, then recreate bucket restrictions and upload objects through Storage APIs. Compare row counts and identifiers for accounts and application tables, object counts and hashes, and check sampled journal-to-object references. Use synthetic accounts to confirm cross-account denial and anonymous access to approved snapshots only. Never use the production URL as a restore target.
5. Keep encrypted copies off-device with access limited to the owner. Record retention, the last successful export and restore, and any missing scope. A synthetic rehearsal establishes the procedure only. A production recovery claim needs an actual encrypted production backup and isolated restore evidence.

Production export and restore require privileged database and Storage access. This repository contains public application configuration and no backup credentials. No production backup or restore has been recorded for this release.

## Android and PWA

- Android application ID is `app.deardaily.mobile`. The APK packages the same Vite UI. Build with Node 22, JDK 21, Android SDK 36 and `npm run android:debug`. Build the unsigned app bundle with `npm run android:bundle`. Keep a future release key offline, back it up, and use the same signing certificate for updates.
- The Android build protects Supabase session storage with Android Keystore AES-GCM. OS backup of app data is disabled. Android uses the platform file chooser and asks for microphone access when needed.
- Android OAuth and email App Links are gated by `VITE_ENABLE_ANDROID_AUTH_LINKS=true`. Before enabling, publish a Digital Asset Links statement at `https://deardailyy.netlify.app/.well-known/assetlinks.json` for the intended release signing certificate only, confirm Android marks the domain verified, and add the exact `/mobile/callback` and `/mobile/recovery` HTTPS URLs to the Supabase redirect allowlist. Google continues to return to Supabase's existing OAuth callback. Test fresh Google login, external email links and recovery on cold start and background return before distributing the enabled build. Avoid publishing a debug certificate association.
- Android password flows also require a successful real Turnstile challenge on the native origin. Test before enabling any production origin changes. The image and voice gateways must explicitly authorize the actual native origin before upload testing. Leave the hosted protections in place during verification.
- Install the PWA from the browser’s install menu or iOS Safari’s Share → Add to Home Screen. The service worker caches only the public offline page and its icon. Journal and Auth requests are always live. Close all open DearDaily web windows and reopen to pick up a waiting service worker update.
